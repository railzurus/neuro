# Подключение ЮKassa

Код готов. Ниже — только то, что делается руками: в кабинете ЮKassa,
в `api/config/secrets.php` на сервере и в планировщике Beget.

Сначала подключаем **тестовый** магазин (деньги не списываются, платёж проходит
тестовой картой), убеждаемся, что всё работает, и меняем два значения
в `secrets.php` на реквизиты боевого магазина. Больше ничего менять не нужно.

---

## Шаг 1. Взять реквизиты магазина

ЛК ЮKassa → **Интеграция → Ключи API**. Нужны две вещи:

- **shopId** — числовой идентификатор магазина;
- **секретный ключ** — у тестового магазина начинается с `test_`.

Ключ показывается один раз при выпуске — сохраните его сразу.

> Тестовый и боевой магазины — это две разные пары «shopId + ключ».
> Переключение между ними = замена двух строк в `secrets.php`.

## Шаг 2. Настроить HTTP-уведомления

ЛК ЮKassa → **Интеграция → HTTP-уведомления**.

- **URL:** `https://медитациямечты.рф/api/yookassa-webhook.php`
  (если поле не принимает кириллицу — тот же адрес в punycode:
  `https://xn--80ahccnbxf5ce4bp7cvc.xn--p1ai/api/yookassa-webhook.php`)
- **События:** `payment.succeeded`, `payment.canceled`, `refund.succeeded`

Уведомления настраиваются **отдельно для тестового и для боевого магазина** —
при переходе на боевой не забудьте настроить их ещё раз.

Именно по этому уведомлению заказ переходит в статус «оплачен» и человеку
уходит письмо со ссылкой.

## Шаг 3. Дописать `secrets.php` на сервере

Файл лежит на Beget в `public_html/api/config/secrets.php` и правится через
файловый менеджер (в git его нет, деплой его не трогает). Добавить/изменить:

```php
'payments_enabled' => true,
'yookassa_shop_id' => '123456',
'yookassa_secret_key' => 'test_XXXXXXXXXXXXXXXXXXXXXXXX',
```

Про ставку НДС в чеке — ниже, шаг 5.

## Шаг 4. Добавить сверку платежей в планировщик

Страховка на случай, если уведомление не дошло (сервер был недоступен).
Beget → **«Планировщик задач»**, запуск **раз в 15–30 минут**:

```bash
php /home/ВАШ_ЛОГИН/медитациямечты.рф/public_html/api/cron/reconcile.php
```

Без неё платёж всё равно подтвердится (ЮKassa повторяет уведомления сутки),
но заказ может «зависнуть» на несколько часов.

## Шаг 5. Проверить ставку НДС в чеке (54-ФЗ)

У магазина подключены **«Чеки от ЮKassa»**: чек в ФНС и покупателю отправляет
касса, но данные для него обязаны уходить вместе с платежом. Мы их передаём —
наименование услуги, количество (1), сумму, ставку НДС, признаки предмета
и способа расчёта, плюс почту покупателя.

От вас нужно одно — **подтвердить у бухгалтера ставку НДС**. По умолчанию
стоит «без НДС»:

```php
'yookassa_receipt' => true,
'yookassa_vat_code' => 1,   // 1 — без НДС
```

Коды: `1` — без НДС, `2` — 0 %, `3` — 10 %, `4` — 20 %, `7` — 5 %, `8` — 7 %,
`11` — 22 %. Для УСН без НДС — `1`; для УСН с НДС — `7` или `8`.
Неверная ставка в чеке — это ошибка в фискальном документе, поэтому лучше
уточнить до первой боевой оплаты.

Если в кассе заведено больше одной системы налогообложения, дополнительно
заполните `yookassa_tax_system_code` (1 — ОСН, 2 — УСН доходы,
3 — УСН доходы минус расходы, 4 — ЕСХН, 5 — патент). Если СНО одна —
оставьте `0`, ЮKassa подставит её сама.

Наименование услуги в чеке и в описании платежа — константа `ORDER_ITEM_NAME`
в [`api/lib/orders.php`](../api/lib/orders.php). Сейчас это
«Персональная аудиозапись «Медитация мечты»» — оно попадёт в чек покупателю,
так что если хочется другой формулировки, скажите.

## Проверка на тестовом магазине

1. На сайте: составить историю → «Купить» → почта → «Перейти к оплате».
2. Должно перекинуть на платёжную форму ЮKassa.
3. Оплатить тестовой картой (номера — в кабинете ЮKassa и в их документации,
   например Visa `4111 1111 1111 1111`; срок — любой будущий, CVC — любой).
4. Вернёт на `/order/<токен>`. Пока идёт подтверждение — «Подтверждаем оплату»,
   через несколько секунд страница сама сменится на «Ваша запись готова».
5. Проверить почту — письмо со ссылкой.
6. В phpMyAdmin в таблице `orders`: `status = paid`, заполнен `payment_id`.
7. В кабинете ЮKassa → «Платежи» — платёж со статусом «Успешный»,
   в разделе HTTP-уведомлений — успешная доставка уведомления.

Чек в тестовом режиме в налоговую не уходит — его проверяем на первой
боевой оплате: письмо с чеком должно прийти на ту же почту, что и ссылка
на заказ.

## Переход на боевой магазин

1. Настроить HTTP-уведомления для боевого магазина (шаг 2).
2. Заменить в `secrets.php` `yookassa_shop_id` и `yookassa_secret_key`
   на боевые (у боевого ключа нет префикса `test_`).
3. Проверить реальной оплатой на 299 ₽ и при необходимости сделать возврат
   из кабинета — возврат тоже придёт уведомлением и переведёт заказ
   в статус `refunded`.

## Если что-то не работает

Первым делом — самопроверка. Она показывает, что видит сервер, и делает
пробный запрос в кассу тем же кодом, что и покупка:

```
https://медитациямечты.рф/api/yookassa-check.php?token=<cron_token>
```

Секреты она не выводит (только префикс и длину ключа). Пробный платёж
создаётся неоплаченным — денег не двигает; отключается параметром
`&payment=0`.

| Симптом | Причина |
|---|---|
| «Не удалось перейти к оплате» | неверные shopId/ключ, либо магазин не прошёл модерацию — точная причина в логе ошибок PHP (панель Beget → «Логи») |
| `Receipt is missing or illegal` | в магазине подключены «Чеки от ЮKassa», а мы их не передаём: в `secrets.php` стоит `'yookassa_receipt' => false`. Поставьте `true` или удалите строку. Тестовый магазин требует чек так же, как боевой |
| Другая ошибка про `receipt` | магазин без подключённых чеков, наоборот, данные чека не примет — тогда `'yookassa_receipt' => false` |
| В логе `Invalid vat_code` / чек не проходит | ставка НДС не совпадает с настройками кассы — см. шаг 5 |
| Оплата прошла, заказ висит в «Подтверждаем оплату» | не настроены HTTP-уведомления, либо уведомление отклонено по IP — смотрите лог `[yookassa-webhook] rejected IP`; временно помогает `'yookassa_verify_ip' => false` |
| В кабинете ЮKassa уведомление «не доставлено» | сервер ответил не 200 — причина в логе ошибок PHP |
| Платёж прошёл, письма нет | вопрос не к кассе — см. `mail_from` в [`beget-setup.md`](beget-setup.md) |

## Как это устроено в коде

```
[/listen] «Купить»
   → POST api/order-create.php
        создаёт заказ (pending) + платёж в ЮKassa (Idempotence-Key = токен заказа)
        ← confirmationUrl
   → форма оплаты ЮKassa
        ├─ redirect на /order/<токен>  (страница сама опрашивает статус ~2 минуты)
        └─ POST api/yookassa-webhook.php
              перепроверяет платёж запросом в API кассы (телу уведомления не верим),
              сверяет сумму → order_mark_paid() → письмо со ссылкой
   ↳ подстраховка: api/cron/reconcile.php добирает «зависшие» pending
```
