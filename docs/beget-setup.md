# Настройка Beget: база данных, почта, cron

Что нужно сделать один раз, чтобы заработали заказы. Всё делается в панели
управления Beget (cp.beget.com) — новый сервер не нужен.

Требования к хостингу: **PHP 7.4 или новее с расширением PDO MySQL** (на Beget
включено по умолчанию; версия PHP переключается в разделе «Сайты»).

---

## Шаг 1. Создать базу данных

1. Панель Beget → раздел **«Базы данных»** (MySQL).
2. Нажать **«Добавить базу данных»**.
3. Имя базы: `neuro`. Beget сам добавит префикс вашего логина — итоговое имя
   получится вида `login_neuro`. Пользователь создаётся с тем же именем.
4. Задать пароль и **сохранить его** — он понадобится на шаге 4.
5. Записать себе три значения:
   - имя базы: `login_neuro`
   - пользователь: `login_neuro`
   - пароль: тот, что задали

Хост базы — `localhost` (сайт и база на одном сервере).

## Шаг 2. Создать таблицы

1. В том же разделе «Базы данных» нажать **phpMyAdmin** напротив вашей базы.
2. Слева выбрать базу `login_neuro`.
3. Открыть вкладку **SQL**.
4. Скопировать туда содержимое файла [`api/schema.sql`](../api/schema.sql)
   и нажать «Вперёд».

Должны появиться три таблицы: `orders`, `consents`, `email_log`.

### Обновление уже работающей базы (миграции)

Если база создана раньше, а в проекте появились новые поля — их нужно донакатить.
Файлы лежат в [`api/migrations/`](../api/migrations/) и выполняются по одному разу
в том же phpMyAdmin (вкладка SQL), по возрастанию номера.

| Миграция | Что делает | Когда нужна |
|---|---|---|
| `001_downloads_and_ratelimit.sql` | счётчик пересборок записи + таблица `rate_limit` | если база создана до 05.08.2026 |

На чистой базе, созданной по актуальному `schema.sql`, миграции не нужны —
там всё уже есть.

## Шаг 3. Создать почтовый ящик

Письмо со ссылкой на заказ уходит от имени ящика на вашем домене — иначе почтовые
службы отправят его в спам.

1. Панель Beget → раздел **«Почта»**.
2. Выбрать домен `медитациямечты.рф` и создать ящик, например `noreply`.

⚠️ **Важно про кириллический домен.** В адресе электронной почты домен должен
быть в punycode. Для `медитациямечты.рф` это `xn--80ahccnbxf5ce4bp7cvc.xn--p1ai`,
то есть адрес отправителя будет:

```
noreply@xn--80ahccnbxf5ce4bp7cvc.xn--p1ai
```

Выглядит некрасиво, но получатель этого почти не видит — в письме отображается
имя отправителя «Медитация мечты». Если хочется красивый адрес, можно отправлять
с `noreply@zurus.tech` (домен на латинице) — тогда ящик создаётся там.

## Шаг 4. Заполнить и загрузить secrets.php

Файл с паролями **не хранится в git** и загружается вручную — деплой его не
перезаписывает.

1. Взять шаблон [`api/config/secrets.example.php`](../api/config/secrets.example.php).
2. Сохранить копию под именем `secrets.php` и заполнить:

```php
'db_host'     => 'localhost',
'db_name'     => 'login_neuro',
'db_user'     => 'login_neuro',
'db_password' => 'пароль_из_шага_1',

'mail_from'      => 'noreply@xn--80ahccnbxf5ce4bp7cvc.xn--p1ai',
'mail_from_name' => 'Медитация мечты',
'site_url'       => 'https://медитациямечты.рф',

'payments_enabled' => false,
'cron_token'       => 'придумайте_случайную_строку',
```

Ключи Yandex (`speechkit_api_key`, `folder_id`) в этом файле уже есть — **не
потеряйте их**, просто дополните файл новыми полями.

3. Загрузить `secrets.php` в папку `api/config/` на сервере (файловый менеджер
   Beget или FTP).

## Шаг 5. Настроить ежедневную очистку

Cron обнуляет тексты историй у заказов, у которых истёк срок ссылки (14 дней).
Это выполнение требования о сроках хранения ПДн.

1. Панель Beget → **«Планировщик задач»** (Crontab).
2. Добавить задачу с запуском **раз в сутки** (например в 4:00):

```bash
php /home/ВАШ_ЛОГИН/медитациямечты.рф/public_html/api/cron/cleanup.php
```

Точный путь можно посмотреть в файловом менеджере Beget — это папка, в которой
лежит `index.html` сайта.

Если с путём не получается, есть запасной вариант — вызов по HTTP:

```bash
curl -s "https://медитациямечты.рф/api/cron/cleanup.php?token=ВАШ_CRON_TOKEN"
```

## Проверка после деплоя

1. Пройти на сайте: составить историю → «Купить» → ввести свою почту →
   подтвердить → «Перейти к оплате».
2. Должно перекинуть на `/order/<длинный_токен>` со словами «Ваша запись готова».
3. Проверить почту — должно прийти письмо со ссылкой.
4. В phpMyAdmin в таблице `orders` должна появиться строка со статусом `paid`,
   в `consents` — запись о согласии, в `email_log` — строка `sent`.
5. Открыть ссылку из письма в другом браузере — заказ должен открыться
   (это и есть проверка того, что данные лежат на сервере, а не в браузере).

### Если что-то не работает

| Симптом | Причина |
|---|---|
| «Service not configured» | нет файла `api/config/secrets.php` на сервере |
| «Database not configured» | не заполнены `db_name` / `db_user` |
| «Database unavailable» | неверный пароль или имя базы; смотрите лог ошибок PHP в панели |
| Заказ создаётся, письма нет | не создан почтовый ящик или `mail_from` не с вашего домена |
| Страница `/order/…` даёт 404 | не сработал SPA-фолбэк — проверьте, что `.htaccess` лежит в корне сайта |
